# 정산 · 거래명세서 · 세금계산서 기획서

> 작성일: 2026-09-11
> 상태: 기획 단계 (코딩 전) — `/grill-me` 세션 결과 반영
> 관련 기존 코드: `app/actions/accounting.ts`, `app/accounting/registration`, `app/accounting/history`, `components/accounting/StatementModal.tsx`

---

## 0. 배경

월별 정산 → 거래명세서 발송 → 세금계산서 발행 → 입금 확인까지 전체 사이클을 코딩 전에 구체화한다. 두 가지는 이미 확정:

- **세금계산서 발행**: 홈택스 수동 발행 + 결과(승인번호 등)만 ERP에 기록
- **거래명세서 발송**: 버튼 클릭 시 **SMTP로 이메일 자동 발송** (v2에서 변경 — 최초안이던 "PDF 다운로드 + 수동 발송"은 폐기)

이 문서는 그 위에 실무 디테일(합산청구 잠금, 발송 방식 선택, 홈택스 엑셀 양식 자동입력, 계산서 취소/수정, 수금 현황 대시보드, 타임라인)을 얹은 최종 기획이다.

## 1단계 — 사용매수 확인 → 월 정산 등록

### 확정 사항
- 기사가 현장에서 사용매수를 확인했든 안 했든, ERP에 입력하는 방법은 **정산 등록 화면에서 담당자가 손으로 입력하는 것 하나뿐**이다. 서비스 일지(`service_logs.meter_bw/meter_col`)와 자동 연동할 필요 없음 — 지금 방식 그대로 유지.

### 신규 요구사항 — 합산청구 그룹 잠금
- 합산청구 그룹(`billing_group_id`)에 묶인 기기 중 **1대라도 이번 달 지침이 안 들어왔으면, 그 그룹 전체의 청구를 생성/발송할 수 없도록 막는다.**
- 화면에 "OO그룹: 2/3대 입력 완료 — 1대 대기 중" 같은 상태 표시 필요.

### 개발 범위
| 항목 | 내용 |
|---|---|
| 검증 로직 | 정산 저장/청구 생성 시, 같은 `billing_group_id`를 가진 기기들이 모두 이번 달 지침을 가졌는지 체크 |
| UI | 그룹별 입력 진행 상태 배지, 미완료 그룹은 "청구 생성" 버튼 비활성화 + 사유 툴팁 |
| 예외 | 그룹 해체(1대만 남는 경우)나 신규 편입 시 잠금 조건 재계산 |

## 2단계 — 거래명세서 발송

### 확정 사항 (v2 변경)
- 명세서 화면에서 **"이메일 발송" 버튼 클릭 시 SMTP로 자동 발송**한다.
- 발송 성공 시 `settlements.sent_at`(발송일)을 자동 기록 — 더 이상 사람이 "발송완료"를 수동 체크하지 않는다.
- 거래처 정보(`clients.email`)에 이메일 주소가 없으면 발송 버튼을 막고 입력을 유도한다.

### 신규 요구사항 — 발송 단위 선택 + 병합 시 수정 가능
- 거래처가 본사/지사 여러 곳일 때, **"따로 보낼지 / 한 번에 합쳐 보낼지"를 사용자가 선택**할 수 있어야 한다.
- 합쳐서 보내는 경우, 합산 명세서의 **회사명·주소 등 표시 내용을 발송 직전에 직접 수정할 수 있는 편집 단계**가 필요하다 (자동 합산 결과가 실무와 다를 수 있음).

### 개발 범위
| 항목 | 내용 |
|---|---|
| SMTP 연동 | 이메일 발송 서비스 선정(Resend/SendGrid 등) 및 API 키·발신 도메인 인증(SPF/DKIM) 설정 |
| 이메일 템플릿 | 제목·본문 기본 양식 + PDF 첨부 |
| 발송 로직 | "발송" 버튼 → 서버에서 PDF 생성 → 이메일 발송 → 성공 시 `sent_at` 기록, 실패 시 에러 메시지 및 재시도 버튼 |
| UI | 명세서 생성 전 "개별 발송 / 통합 발송" 선택 라디오 |
| 통합 발송 편집 | `StatementModal`에 편집 가능한 헤더 필드(수신 회사명, 주소 등) 추가 — 저장하지 않고 그 발송 건에만 적용되는 오버라이드 |
| DB | `settlements`에 `sent_at`(발송일) 컬럼 추가, `clients.email` 필수값 검증 |
| 예외 처리 | 발송 실패(주소 오류, 서비스 장애) 시 상태를 "발송 실패"로 남기고 재발송 가능하게 함 |

## 3단계 — 세금계산서 발행 (홈택스 엑셀 연동)

### 확정 매커니즘 (v4 — 발행 전 생성 + 발행 후 가져오기, 양방향 모두 구현)
실제 홈택스 "매출 전자(수정) 세금계산서 목록조회" 다운로드 파일과, 실제 홈택스 **일괄등록 업로드 양식**(`세금계산서등록양식(일반).xls`, 비밀번호 보호 → 사본으로 사본 확보 후 59개 컬럼 구조 확인, 2026-09-11) 두 가지 모두 실물로 검증했다. 당초 "업로드 양식 자동생성은 폐기, import만" 이라고 적었던 v3 결정은 이후 사용자가 실제로 원하는 흐름(발행 **전** 엑셀 생성 → 홈택스 업로드 → 발행 **후** 결과를 ERP에 반영)을 다시 확인하면서 뒤집혔고, 지금은 아래 두 기능이 모두 구현되어 있다.

**(A) 발행 전 — 홈택스 일괄등록 업로드 엑셀 생성**
1. 설정 > 계정에 저장된 우리 회사 사업자 정보(사업자번호·대표자명·주소 등)를 공급자 정보로 사용
2. **청구 이력** 페이지 첫 화면(검색 전 — 그 달 등록된 정산 건 목록)에서 체크박스로 원하는 건들을 고르고 "선택한 N건 홈택스 엑셀 일괄 다운로드" 클릭 → 홈택스 공식 업로드 양식(59컬럼)에 맞춰 `.xlsx` 다운로드. 건별로도 각 정산 건의 "🧾 세금계산서" 버튼에서 1건짜리 엑셀만 따로 받을 수 있다.
3. 사용자가 홈택스에서 그 파일을 직접 업로드해 일괄 발급 (발급 자체는 여전히 홈택스에서 수동)

**구현 완료** ([`utils/hometaxBulkExcel.ts`](../utils/hometaxBulkExcel.ts), `app/actions/accounting.ts`의 `getHometaxUploadDataForSettlementsAction`/`getHometaxUploadDataForSettlementAction`, [`components/accounting/HistoryDefaultList.tsx`](../components/accounting/HistoryDefaultList.tsx)의 일괄 다운로드 버튼과 [`components/accounting/TaxInvoiceModal.tsx`](../components/accounting/TaxInvoiceModal.tsx)의 단건 다운로드 버튼).

**(B) 발행 후 — 홈택스 발급 결과 가져오기(import)**
1. 홈택스 **전자세금계산서 발급 > 목록조회 > 엑셀 다운로드**로 받은 파일을 그대로 ERP에 업로드
2. ERP가 파일을 파싱해 **거래처명 + 작성월**로 정산 건을 자동으로 찾고, 승인번호·발행일·금액을 `tax_invoices`에 자동 기록
3. 거래처를 못 찾거나, 그 달 정산 건이 없거나, 금액이 ERP 청구액과 다르면 자동 기록하지 않고 사유와 함께 목록으로 보여줌 (수동 확인 필요)

**구현 완료** ([`utils/taxInvoiceExcel.ts`](../utils/taxInvoiceExcel.ts), [`app/actions/taxInvoice.ts`](../app/actions/taxInvoice.ts) `importTaxInvoicesFromExcelAction`, [`components/accounting/TaxInvoiceExcelModal.tsx`](../components/accounting/TaxInvoiceExcelModal.tsx)) — **수금 현황** 화면의 "세금계산서 엑셀로 가져오기" 버튼에서 바로 사용 가능. 이 가져오기(또는 청구 이력에서의 수동 발행 기록)가 수금 현황에 해당 건이 나타나게 만드는 유일한 통로다.

같은 승인번호가 여러 줄(품목이 여러 개)로 반복되는 것도 승인번호 기준으로 1건으로 합쳐서 처리한다.

두 파일 모두 사용자 PC에 수동 백업하는 것을 전제로 한다 (ERP가 폴더를 감시하거나 자동 인식하지는 않음 — 생성 파일은 다운로드 폴더에, 발급 완료 파일은 사용자가 직접 골라 업로드).

### 신규 요구사항 — 계산서 취소 · 수정 처리
세금계산서는 발행 후에도 국세청 규정상 **취소(당초 건 무효화)** 또는 **수정발행(음수/양수 수정 세금계산서)** 이 실무에서 자주 발생한다. 이를 위해:

- `tax_invoices` 레코드에 **상태 필드** 필요: `정상 | 취소 | 수정발행됨`
- 수정/취소 건은 **원본 레코드를 참조**하는 방식으로 저장 (예: `original_invoice_id` — 자기 자신을 참조하는 FK)
- 화면에서 원본과 수정/취소 건이 **한 묶음으로 보이도록** (타임라인처럼 연결 표시)
- 금액은 원본 그대로 두고, 수정/취소 건에 새 승인번호·발행일·금액(취소 시 마이너스)을 별도로 기록

### 개발 범위
| 항목 | 내용 |
|---|---|
| 홈택스 엑셀 양식 생성기 | ✅ 완료 — 청구 데이터 → 홈택스 업로드 양식 59컬럼 매핑 → `xlsx` 라이브러리로 파일 생성 ([`utils/hometaxBulkExcel.ts`](../utils/hometaxBulkExcel.ts)) |
| 다운로드 | ✅ 완료 — 브라우저에서 파일로 저장 (서버 미보관) |
| `tax_invoices` 테이블 | `id, settlement_id, status(정상/취소/수정발행됨), original_invoice_id, issued_at, approval_no, amount, memo, created_by` |
| UI | 발행 기록 입력 폼 + 취소/수정발행 등록 버튼 + 원본-수정 묶음 표시 |
| 검증 | 홈택스 엑셀 양식은 국세청 정책 변경 시 컬럼이 바뀔 수 있으므로, 양식 버전을 변수로 분리해 나중에 쉽게 수정 가능하게 설계 |

## 4단계 — 수금 현황 대시보드 (구 "미수금 현황")

### 청구 이력 vs 수금 현황 — 홈택스를 기준으로 한 역할 분리 (v5)
두 화면이 서로 다른 역할을 맡도록 명확히 나눴다:

- **청구 이력 페이지 = 홈택스 이전 단계.** 월 정산을 등록·수정하고, 발행 전 상태인 건들을 모아 홈택스 일괄등록 엑셀을 받는 곳(3단계 (A)). 검색 전 첫 화면에도 이번 달 등록된 정산 건 전체가 보인다 — 아직 세금계산서가 없어도 다 보임. **입금 여부(완납/미수금)는 이 단계의 관심사가 아니므로 표시하지 않는다** — 아직 청구서를 발행하는 단계일 뿐, 돈을 받는 단계가 아니기 때문. 거래처 행의 "열기"를 누르면 페이지 이동 없이 그 아래에 상세(기계별 청구 내역)가 펼쳐지며, 체크박스로 항목을 골라 수정(1건만)·삭제·재청구(여러 건 가능)를 처리한다.
- **수금 현황 페이지 = 홈택스 이후 단계.** "고객에게 실제로 돈이 들어왔는지"를 확인·기록하는 곳. 홈택스에서 발급이 **완료**된 뒤, 그 결과 엑셀을 ERP에 가져오거나(3단계 (B)) 청구 이력에서 수동으로 발행 기록을 남겨야만 — 즉 `tax_invoices`에 정상 상태 레코드가 생겨야만 — 이 화면에 나타난다. 세금계산서가 아직 없는(`미발행`) 정산 건은 이 화면에서 제외된다.

### 요구사항
한눈에 보는 표로 (발급 완료된 건에 한해):
- **미수금**(청구했는데 입금 안 된 금액)
- **초과입금**(입금액이 청구액보다 많은 경우)
- 거래처별 **거래명세서 발송 여부**
- 거래처별 **세금계산서 발행 상태**(정상/취소/수정발행)

### 개발 범위
| 항목 | 내용 |
|---|---|
| 데이터 | `settlements`(청구액, 입금액, `is_paid`) + `sent_at`(2단계) + `tax_invoices` 상태(3단계) 조인 — `getBillingDashboardAction`은 전체를 반환하고, 청구 이력(첫 화면)은 전체를, 수금 현황은 `tax_invoice_status !== '미발행'`으로 필터링해 사용 |
| 계산 | 미수금 = 청구액 − 입금액 (양수), 초과입금 = 입금액 − 청구액 (양수) |
| UI | 거래처 × (청구액, 입금액, 미수/초과, 명세서 발송 O/X, 계산서 발행 상태) 표. 미수금만 보기 토글. `tax_invoice_status`가 `미발행`인 행은 애초에 표시하지 않음 |

## 5단계 — 기간별 계산서 발행 타임라인

### 요구사항
기간(예: 분기, 연도)을 지정하면 그 기간 동안의 세금계산서 발행 내역(원본/취소/수정 흐름 포함)을 시간순으로 볼 수 있는 화면.

### 개발 범위
| 항목 | 내용 |
|---|---|
| 재사용 | 기존 `fetchClientTimelineAction`을 확장해 `tax_invoices` 이력도 함께 반환 |
| UI | 거래처 타임라인 화면에 "세금계산서" 트랙 추가 — 발행/취소/수정 이벤트를 순서대로 표시 |

## 더 쉬운 대안 (MVP 축소판)

### 4단계 — 부분입금 처리
새 필드를 만들지 않고, **정산 메모에 텍스트로 기록**하는 방식으로 시작한다.
- 예: 메모란에 `"150,000원만 입금, 나머지는 다음 달"`
- 입금 확정(`is_paid` 토글)은 **완납된 시점에만** 누른다
- 개발량 0 — 지금 스키마 그대로 운영 가능. 실제로 부분입금이 자주 발생하면 그때 전용 필드(`paid_amount`, `remaining_amount`)로 승격
