📘 [정산 및 회계 관리] 시스템 상세 구축 계획서
1. 🏗️ 시스템 구조 및 UI 기획
1-1. 전체 레이아웃
메뉴: 사이드바에 📄 정산 및 회계 관리 탭 추가 (아이콘: 계산기 모양 추천)

페이지 구조: /accounting 경로 사용. 하나의 페이지를 상하 2단으로 분리.

상단 (Section A): 사용매수 등록 및 청구 (아코디언 형태 - 기본 펼침)

하단 (Section B): 청구 이력 조회 및 수정 (아코디언 형태 - 기본 펼침)

1-2. 기능별 상세 프로세스
A. 자산(기계) 등록 및 교체 (선행 작업)
신규 등록 시 (InventoryForm):

제품 상태 선택: ( ) 새제품 / ( ) 중고 라디오 버튼 제공.

새제품: 초기 카운터 입력란 비활성화 (자동 0).

중고: 초기 카운터(흑백/컬러/A3) 입력란 활성화 → 수동 입력 값 저장.

기계 교체 시 (ClientList):

기존 철수 버튼 옆에 🔄 교체 버튼 추가.

클릭 시: 기존 기계 상태를 교체전(철수)로 변경 → 즉시 신규 자산 등록 팝업/화면으로 이동.

결과: 해당 거래처에 **[구형 기계]**와 **[신형 기계]**가 공존하게 됨.

B. 사용매수 등록 (핵심 기능)
검색 필터:

청구 년/월 선택 (예: 2024년 2월).

거래처명 검색 / ☑️ 미등록 거래처만 보기 필터.

등록 리스트 (테이블):

행(Row) 구성: 거래처 기준이 아닌 기계(Inventory) 기준으로 나열하되, 같은 거래처 기계는 묶어서 표시.

전월 카운터 자동 로딩:

기본: 지난달 settlement_details의 당월 카운터를 가져옴.

데이터 없음(첫 등록): inventory 테이블의 초기 카운터 값을 가져옴.

당월 카운터 입력:

사용자가 검침한 흑백, 컬러, A3 카운터 입력.

실시간 계산 (Simulation):

입력 즉시 (당월 - 전월) x 가중치 계산하여 사용량 표시.

거래처 내 모든 기계의 사용량을 합산하여 예상 청구액 실시간 표시.

최종 저장:

체크박스 선택 후 청구 확정 버튼 클릭.

DB에 settlements(통합 청구서)와 settlement_details(기계별 명세)가 동시에 저장됨.

C. 사용매수 조회
조회: 기간별, 거래처별 청구 완료 내역 조회.

수정: 수정 시 "다음 달 전월 데이터와 불일치할 수 있습니다" 경고 메시지 출력.

거래처 연동: ClientList 상세 화면에서도 해당 거래처의 청구 이력 탭 생성.
